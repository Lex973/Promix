# Перенос PROMIX на сервер

Пошагово, в том порядке, в каком это прошло на репетиции 13 сентября 2026
(чистый WordPress 7.1 + WooCommerce 11.1, PHP 8.2). Шаги, где на репетиции
что-то ломалось, помечены ⚠ — там порядок важен.

## 0. Хостинг TimeWeb

- Тариф с сервером в России: форма заказа собирает ФИО, телефон и почту, по 152-ФЗ
  база должна лежать в РФ.
- **PHP 8.2** — как в Local, на нём тема проверена (минимум для темы — 8.1).
  MySQL 8. Расширения `mysqli`, `intl`, `mbstring`, `gd` или `imagick` — стандартный
  набор TimeWeb, отдельно включать обычно не нужно.
- **SSL** (Let's Encrypt) выпустить в панели сразу после привязки домена.
- На виртуальном хостинге TimeWeb Apache стоит за nginx, `.htaccess` работает —
  служебные файлы темы закрывает её `.htaccess`. На VPS с голым nginx нужно
  правило из README («Перенос на сервер»).
- **Бэкапы:** в панели включить ежедневные копии сайта и базы. Перед импортом
  товаров (шаг 6) и перед тем, как заказчик начнёт заполнять админку, сделать
  ручную копию — откатываться будет к ней.

## 1. WordPress

1. Установить WordPress (русский), включить HTTPS на хостинге — все адреса сайта должны быть `https://`.
   ⚠ Язык закрепить настройкой: «Настройки → Общие → Язык сайта: Русский» или
   `wp site switch-language ru_RU` (опция `WPLANG = ru_RU`). Русская сборка держит
   язык отметкой в `wp-includes/version.php`, и первое же обновление ядра её стирает —
   сайт становится английским, цены — «1,074.84 ₽».
2. **Настройки → Общие:** название `PROMIX`, краткое описание `Малярный центр в Казани`
   (из них собирается `<title>` главной), часовой пояс `Москва`.
3. **Настройки → Постоянные ссылки:** «Название записи» (`/%postname%/`). ⚠ Сделать
   до `wc-setup.php`, иначе адреса каталога не соберутся.
4. **Настройки → Чтение:** после запуска снять галочку «Попросить поисковые системы
   не индексировать сайт». До запуска пусть стоит.

## 2. Тема

1. **Внешний вид → Темы → Добавить → Загрузить тему:** `promix.zip`, активировать.
   Или распаковать в `wp-content/themes/promix/`. Carbon Fields лежит в `vendor/`
   внутри темы, composer на сервере не нужен.
2. Проверить, что открылась главная с текстами по умолчанию (поля пустые — тема
   показывает согласованные тексты сама).

## 3. WooCommerce

1. **Плагины → Добавить:** WooCommerce, установить, активировать.
2. Мастер настройки закрыть — все его вопросы решает `wc-setup.php` (шаг 5).
3. Других плагинов не ставить: кэш, SEO, SMTP и антиспам в теме свои или не нужны.

## 4. Страницы

1. **Главная** — новая страница, заголовок «Главная», в правой колонке
   «Шаблон» → **Главная PROMIX**. Опубликовать.
2. **Каталог** — новая страница, заголовок «Каталог», **ярлык `catalog`**.
   Содержимое пустое. ⚠ `wc-setup.php` ищет её по ярлыку.
3. **Политика конфиденциальности** — WordPress уже создал черновик с таким
   названием (**Страницы → Черновики**). Открыть его, стереть шаблонный текст,
   вставить текст из `_content/privacy-policy.md` (заголовки — как заголовки,
   списки — как списки), в поле «Отрывок» написать «Какие данные собирает
   сайт PROMIX, зачем и как их удалить.», опубликовать. ⚠ Не создавать вторую
   страницу — у новой будет адрес `/privacy-policy-2/`.
4. **Настройки → Чтение:** «Статическая страница», главная — «Главная».
5. **Настройки → Конфиденциальность:** выбрать «Политика конфиденциальности».
   Оттуда ссылка сама попадает в подвал, форму заявки, баннер про cookie и оформление заказа.

## 5. wc-setup.php

1. Открыть `_tools/wc-setup.php`, заменить `СЕКРЕТ` на случайную строку из 12+ латинских
   букв и цифр.
2. Положить файл в корень сайта (рядом с `wp-config.php`), открыть
   `https://домен/wc-setup.php?k=СЕКРЕТ`, дождаться `rewrite rules dropped`.
3. **Удалить файл.**
4. Открыть `/catalog/` — на этом запросе WordPress пересобирает адреса.

Что делает скрипт: страница «Каталог» становится магазином Woo, лишние страницы
Woo (магазин, возвраты, личный кабинет, «Пример страницы») и запись «Привет, мир!»
уходят в корзину,
адреса `/catalog/раздел/`, `/product/товар/`, рубли с копейками (показываются
только там, где они есть в цене из 1С — у 6 товаров),
Россия/Казань, отзывы, купоны, учёт остатков и налоги выключены, гостевое
оформление, HPOS, мастер и подсказки погашены, слежка выключена.

⚠ HPOS (заказы в своих таблицах) включается скриптом на чистой базе. Если
заказы уже были — только через «WooCommerce → Настройки → Дополнительно → Функции».

## 6. Товары

1. **Товары → Импорт** → `woo-import.csv`. Галочку «Обновлять существующие
   товары» **не ставить** (с ней новые строки пропускаются). Мастер сам сопоставит
   колонки (`Categories` → «Категории», `Brands` → «Бренды»). 411 товаров (418 в прайсе минус `_tools/excluded.py`),
   4 раздела и 27 подразделов (в колонке они записаны как «Раздел > Подраздел»,
   импортёр заводит вложенность сам), 28 брендов. Два подраздела после этого
   шага пустые и в каталоге скрыты: декоративные штукатурки (их наполняет шаг 4)
   и инструменты для лент и плёнок.
2. **Товары → Импорт** → `woo-descriptions.csv`, теперь галочку «Обновлять
   существующие товары» **поставить** — совпадение по артикулу, ~30 секунд.
3. Порядок разделов: импортёр заводит их по алфавиту, а в фильтре они должны идти
   как в структуре заказчика. Положить в корень сайта `_tools/wc-recategorize.php`
   (заменить `СЕКРЕТ`) вместе с `wc-categories.csv`, открыть
   `/wc-recategorize.php?k=СЕКРЕТ` и удалить оба файла. Этот же скрипт переводит
   на новые разделы **уже наполненный** магазин: тогда рядом кладётся ещё и
   `woo-descriptions.csv`, и шаги 1–2 не нужны.
4. **Декоративные покрытия AlterItaly** (15 позиций, в 1С их нет — список и цены
   «от … за м²» дал заказчик): положить в корень сайта `_tools/wc-decor.php`
   (заменить `СЕКРЕТ`), `decor.csv` и папку `img/` из комплекта, открыть
   `/wc-decor.php?k=СЕКРЕТ&dry=1`, затем без `&dry=1` — «заведено 15». Удалить
   скрипт, CSV и `img/`. Повторный запуск обновляет те же товары по артикулу.
5. Проверить: `/catalog/` — «Найдено 426 товаров», `/catalog/instrument/shpateli-i-pravila/`
   открывается, у товара есть описание; `/catalog/materialy/dekorativnye-shtukaturki/` —
   15 позиций с образцами цвета и ценами «от … ₽/м²».

## 7. wp-config.php

Ниже строки `/* Add any custom values between this line and the "stop editing" line. */`:

```php
// MAX: бот через @MasterBot, номер чата — «Инструменты → MAX» в админке.
define( 'PROMIX_MAX_TOKEN', '…' );
define( 'PROMIX_MAX_CHAT', 0 );

// Почта через SMTP mail.ru с ящика promix.kazan@mail.ru.
// Пароль — «пароль для внешних приложений» из настроек mail.ru, не от почты.
define( 'PROMIX_SMTP_HOST', 'smtp.mail.ru' );
define( 'PROMIX_SMTP_PORT', 465 );
define( 'PROMIX_SMTP_SECURE', 'ssl' );
define( 'PROMIX_SMTP_USER', 'promix.kazan@mail.ru' );
define( 'PROMIX_SMTP_PASS', '…' );

// Настоящий cron вместо WP-Cron (шаг 8).
define( 'DISABLE_WP_CRON', true );

// Боевой сайт: ошибки в лог, не на экран.
define( 'WP_ENVIRONMENT_TYPE', 'production' );
define( 'WP_DEBUG', false );
```

⚠ Если в `wp-config.php` уже есть строка `define( 'WP_DEBUG', … )` от установщика,
не дублировать её, а поправить значение: второй `define` той же константы даёт
предупреждение.

Пока `PROMIX_SMTP_HOST` не задан, письма (заявки и письма Woo о заказах) идут
через sendmail хостинга с адреса `noreply@домен` — так работает, но чаще
попадает в спам. ⚠ Отправитель «от promix.kazan@mail.ru» без SMTP mail.ru
отклоняет (DMARC `p=reject`), поэтому тема сама ставит Woo `noreply@домен`,
что бы ни стояло в настройках Woo. **До запуска SMTP нужен обязательно** и
доставку проверить по реальному ящику, а не по журналу Woo («отправлено»
там значит только, что письмо принял сервер хостинга). Если письмо не ушло,
в админке появляется красная плашка с текстом ошибки.

## 8. Cron

В панели хостинга — задание раз в 5 минут:

    */5 * * * * php /путь/к/сайту/wp-cron.php >/dev/null 2>&1

или `curl -s https://домен/wp-cron.php >/dev/null`. Нужен WooCommerce
(Action Scheduler) и запасному пути отправки в MAX.

## 9. Настройки темы

1. **Контакты PROMIX** (пункт в меню админки): телефон, адрес, режим работы,
   почта для заявок, ссылка на MAX, реквизиты. Пустое поле = значение по умолчанию
   из темы, они уже верные по карте партнёра; заполнить нужно только **ОГРН**
   и **ссылку на MAX**.
2. **Внешний вид → Меню** — не обязательно: без меню тема показывает свои пункты
   (Каталог, Бренды, О компании, Отзывы, Контакты).
3. **Инструменты → MAX:** после того как менеджер написал боту, взять номер чата
   в `PROMIX_MAX_CHAT`, нажать «Отправить тестовое сообщение».

## 9а. Защита и обновления

- В корневой `.htaccess` (над блоком `# BEGIN WordPress`) — запрет `xmlrpc.php`:
  ```
  <Files xmlrpc.php>
      Require all denied
  </Files>
  ```
  Тема и сама выключает XML-RPC, перебор логинов через REST и `?author=N`,
  ограничивает вход пятью попытками на 15 минут (`inc/security.php`); запрет
  на уровне сервера — чтобы запросы к xmlrpc.php не доходили до PHP.
- Отображаемое имя администратора — не логин: `wp user update 1 --display_name=PROMIX`.
- Обновить ядро и Woo до последних исправлений той же ветки
  (`wp core update --minor`, `wp plugin update woocommerce --minor`) после
  бэкапа; потом пройти шаг 10. Автообновления minor работают через cron — без
  шага 8 они не придут.

- [ ] Товар в корзину → `/cart/` → `/checkout/` → заказ: страница «Заказ принят»,

      сообщение в MAX, заказ в «WooCommerce → Заказы» со статусом «На удержании».
- [ ] Заявка через «Спросить у технолога»: письмо, MAX, запись в «Заявки».
- [ ] `/privacy-policy/` — без квадратных скобок в тексте.
- [ ] `/nope/` — своя 404.
- [ ] `/wp-content/themes/promix/README.md` и `/wp-content/themes/promix/_tools/`
      отвечают 403/404. На Apache это делает `.htaccess` темы, под nginx —
      правило из README («Перенос на сервер»).
- [ ] В корне сайта нет копий конфига и служебных скриптов: `/wp-config.php.bak`,
      `/wp-config.php.old`, `/wc-setup.php`, `/wc-recategorize.php`, `/*.csv` — 404.
      Копия `wp-config.php` с расширением не `.php` отдаётся как текст вместе

- [ ] `/wp-sitemap.xml` открывается, в нём нет записей и рубрик (`…-posts-post-…`,

- [ ] `http://` → `https://` редирект.
- [ ] `curl -I https://домен/` — в ответе есть `X-Content-Type-Options`,
      `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` (их отдаёт тема).
- [ ] Лимит заявок считается по посетителю, а не общий на сайт: заявка с
      компьютера и сразу следом с телефона по мобильной сети — обе проходят.

- [ ] На телефоне: первый экран — фото офиса сверху, кнопка «Перейти в каталог»
      видна без прокрутки; шапка не шире экрана.

## 11. Переезд с технического адреса на домен

Сайт сначала разворачивается на техническом адресе (`ce098228.tw1.ru`),
домен подключается потом — без повторного переноса:

1. Бэкап: `wp db export ~/backup/before-domain.sql`, копию скачать к себе.
2. В панели: «Домены и SSL» → привязать домен к сайту, выпустить SSL на
   домен (и `www`). Дождаться, пока `https://домен/` откроет заглушку или сайт.
3. Адреса в базе (в том числе сериализованные опции Woo и Carbon Fields):
   ```
   wp search-replace 'https://ce098228.tw1.ru' 'https://домен' --all-tables --precise --skip-columns=guid --dry-run
   wp search-replace 'https://ce098228.tw1.ru' 'https://домен' --all-tables --precise --skip-columns=guid
   wp cache flush
   ```
4. Технический адрес — 301 на домен (в корневой `.htaccess`, над блоком WordPress),
   иначе после снятия «не индексировать» он станет зеркалом в поиске:
   ```
   RewriteEngine On
   RewriteCond %{HTTP_HOST} ^ce098228\.tw1\.ru$ [NC]
   RewriteRule ^(.*)$ https://домен/$1 [R=301,L]
   ```
5. Отправитель писем (`noreply@домен`) тема собирает из адреса сайта — меняется
   сам; с SMTP — ящик SMTP. Проверить письмо по заявке и заказу.
6. Шаг 10 целиком на новом домене; затем снять «не индексировать» (шаг 1.4),
   проверить `/wp-sitemap.xml`, `/robots.txt`.

## Что вылезло на переносе на TimeWeb (29 сентября 2026)

Сервер `vh460.timeweb.ru`, тариф Optimo, технический адрес `ce098228.tw1.ru`.
Сайт разворачивался по SSH с ключом, а не через админку.

- На виртуальном хостинге есть **wp-cli**, PHP 8.2, git, composer. WordPress,
  WooCommerce 11.1.0 и настройки ставились командами; импорт шагов 6.1–6.2 —
  `wp eval-file wc-import.php woo-import.csv woo-descriptions.csv` (тот же
  импортёр Woo, бренды подключает сам); шаги 5, 6.3, 6.4 — веб-скриптами, как выше.
- ⚠ `wp config create --prompt=dbpass` **печатает введённый пароль** в вывод.
  Пароль базы — в файл на сервере (`read -s`, права 600), в `wp-config.php` —
  заглушкой, которую подменяет `php -r` из файла; файл после — удалить.
- ⚠ `wp rewrite structure` из консоли не пишет `.htaccess` — адреса `/catalog/`
  отдают 404. Корневой `.htaccess` WordPress (блок `# BEGIN WordPress`) создать руками.
- Cron — только через панель («Crontab»), `crontab` в SSH запрещён.
- `readme.html`, `license.txt`, `wp-config-sample.php` из корня удалены — первый
  выдаёт версию WordPress.
- Пока «не индексировать» включено, `/wp-sitemap.xml` отдаёт 404 — так и должно быть.
- ⚠ После `wp core update` сайт стал английским (`WPLANG` не был задан, язык держался
  на `$wp_local_package` в version.php) — цены «1,500 ₽», «1,074.84 ₽». Лечится
  `wp site switch-language ru_RU`; теперь это шаг 1.1.
- Бэкап базы перед импортом: `wp db export ~/backup/…sql` (папка вне сайта).

## Что вылезло на репетиции

- `flush_rewrite_rules()` в `wc-setup.php` записывал старые адреса: разделы и
  бренды отвечали 404. Исправлено — скрипт удаляет правила, WordPress собирает
  их при следующем запросе (потому шаг 5.4).
- Черновик «Политика конфиденциальности» от WordPress занимает ярлык
  `privacy-policy` — новая страница получает `-2`. Использовать черновик.
- Импорт с галочкой «Обновлять существующие» не создаёт новые товары —
  порядок в шаге 6 важен.
- Колонка цены в выгрузке из 1С называлась то «Цена», то «Цена, ₽» —
  `wc-import-csv.py` теперь ищет её по началу названия.
