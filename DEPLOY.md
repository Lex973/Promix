# Перенос PROMIX на сервер

Пошагово, в том порядке, в каком это прошло на репетиции 13 сентября 2026
(чистый WordPress 7.1 + WooCommerce 11.1, PHP 8.2). Шаги, где на репетиции
что-то ломалось, помечены ⚠ — там порядок важен.

## Что взять с собой

| Что | Откуда |
|---|---|
| Архив темы `promix.zip` | `git archive --format=zip -o promix.zip HEAD` — без `_tools/` и `_content/` |
| `wc-setup.php` | `_tools/wc-setup.php` из репозитория (в архив не входит) |
| `woo-import.csv`, `woo-descriptions.csv` | `python _tools/wc-import-csv.py` и `python _tools/wc-descriptions.py` — из прайса `docs/data/katalog-dlya-sayta.csv`, результат там же |
| Текст политики | `_content/privacy-policy.md`; заменить `[ОГРН]` и `[ДАТА]` |
| Константы для `wp-config.php` | токен и чат MAX, SMTP (см. шаг 7) |

## 1. WordPress

1. Установить WordPress (русский), включить HTTPS на хостинге — все адреса сайта должны быть `https://`.
2. **Настройки → Общие:** название `PROMIX`, краткое описание `Малярный центр в Казани`
   (из них собирается `<title>` главной), часовой пояс `Москва`.
3. **Настройки → Постоянные ссылки:** «Название записи» (`/%postname%/`). ⚠ Сделать
   до `wc-setup.php`, иначе адреса каталога не соберутся.
4. **Настройки → Чтение:** после запуска снять галочку «Попросить поисковые системы
   не индексировать сайт». До запуска пусть стоит.

## 2. Тема

1. **Внешний вид → Темы → Добавить → Загрузить тему:** `promix.zip`, активировать.
   Или распаковать в `wp-content/themes/promix/`. Carbon Fields лежит в `vendor/`
   внутри темы, composer на сервере не нужен.
2. Проверить, что открылась главная с текстами по умолчанию (поля пустые — тема
   показывает согласованные тексты сама).

## 3. WooCommerce

1. **Плагины → Добавить:** WooCommerce, установить, активировать.
2. Мастер настройки закрыть — все его вопросы решает `wc-setup.php` (шаг 5).
3. Других плагинов не ставить: кэш, SEO, SMTP и антиспам в теме свои или не нужны.

## 4. Страницы

1. **Главная** — новая страница, заголовок «Главная», в правой колонке
   «Шаблон» → **Главная PROMIX**. Опубликовать.
2. **Каталог** — новая страница, заголовок «Каталог», **ярлык `catalog`**.
   Содержимое пустое. ⚠ `wc-setup.php` ищет её по ярлыку.
3. **Политика конфиденциальности** — WordPress уже создал черновик с таким
   названием (**Страницы → Черновики**). Открыть его, стереть шаблонный текст,
   вставить текст из `_content/privacy-policy.md` (заголовки — как заголовки,
   списки — как списки), в поле «Отрывок» написать «Какие данные собирает
   сайт PROMIX, зачем и как их удалить.», опубликовать. ⚠ Не создавать вторую
   страницу — у новой будет адрес `/privacy-policy-2/`.
4. **Настройки → Чтение:** «Статическая страница», главная — «Главная».
5. **Настройки → Конфиденциальность:** выбрать «Политика конфиденциальности».
   Оттуда ссылка сама попадает в подвал, форму заявки, баннер про cookie и оформление заказа.

## 5. wc-setup.php

1. Открыть `_tools/wc-setup.php`, заменить `СЕКРЕТ` на случайную строку из 12+ латинских
   букв и цифр.
2. Положить файл в корень сайта (рядом с `wp-config.php`), открыть
   `https://домен/wc-setup.php?k=СЕКРЕТ`, дождаться `rewrite rules dropped`.
3. **Удалить файл.**
4. Открыть `/catalog/` — на этом запросе WordPress пересобирает адреса.

Что делает скрипт: страница «Каталог» становится магазином Woo, лишние страницы
Woo (магазин, возвраты, личный кабинет, «Пример страницы») уходят в корзину,
адреса `/catalog/раздел/`, `/product/товар/`, `/brand/марка/`, рубли без копеек,
Россия/Казань, отзывы, купоны, учёт остатков и налоги выключены, гостевое
оформление, HPOS, мастер и подсказки погашены, слежка выключена.

⚠ HPOS (заказы в своих таблицах) включается скриптом на чистой базе. Если
заказы уже были — только через «WooCommerce → Настройки → Дополнительно → Функции».

## 6. Товары

1. **Товары → Импорт** → `woo-import.csv`. Галочку «Обновлять существующие
   товары» **не ставить** (с ней новые строки пропускаются). Мастер сам сопоставит
   колонки (`Categories` → «Категории», `Brands` → «Бренды»). 1 451 товар,
   13 разделов, 31 бренд; на репетиции импорт занял около четырёх минут.
2. **Товары → Импорт** → `woo-descriptions.csv`, теперь галочку «Обновлять
   существующие товары» **поставить** — совпадение по артикулу, ~30 секунд.
3. Проверить: `/catalog/` — «Найдено 1 451 товар», `/catalog/shpateli-i-lezviya/`
   и `/brand/storch/` открываются, у товара есть описание.

## 7. wp-config.php

Ниже строки `/* Add any custom values between this line and the "stop editing" line. */`:

```php
// MAX: бот через @MasterBot, номер чата — «Инструменты → MAX» в админке.
define( 'PROMIX_MAX_TOKEN', '…' );
define( 'PROMIX_MAX_CHAT', 0 );

// Почта через SMTP mail.ru с ящика promix.kazan@mail.ru.
// Пароль — «пароль для внешних приложений» из настроек mail.ru, не от почты.
define( 'PROMIX_SMTP_HOST', 'smtp.mail.ru' );
define( 'PROMIX_SMTP_PORT', 465 );
define( 'PROMIX_SMTP_SECURE', 'ssl' );
define( 'PROMIX_SMTP_USER', 'promix.kazan@mail.ru' );
define( 'PROMIX_SMTP_PASS', '…' );

// Настоящий cron вместо WP-Cron (шаг 8).
define( 'DISABLE_WP_CRON', true );
```

Пока `PROMIX_SMTP_HOST` не задан, письма идут через sendmail хостинга с адреса
`noreply@домен` — так работает, но чаще попадает в спам. Если письмо не ушло,
в админке появляется красная плашка с текстом ошибки.

## 8. Cron

В панели хостинга — задание раз в 5 минут:

    */5 * * * * php /путь/к/сайту/wp-cron.php >/dev/null 2>&1

или `curl -s https://домен/wp-cron.php >/dev/null`. Нужен WooCommerce
(Action Scheduler) и запасному пути отправки в MAX.

## 9. Настройки темы

1. **Контакты PROMIX** (пункт в меню админки): телефон, адрес, режим работы,
   почта для заявок, ссылка на MAX, реквизиты. Пустое поле = значение по умолчанию
   из темы, они уже верные по карте партнёра; заполнить нужно только **ОГРН**
   и **ссылку на MAX**.
2. **Внешний вид → Меню** — не обязательно: без меню тема показывает свои пункты
   (Каталог, Бренды, О компании, Отзывы, Контакты).
3. **Инструменты → MAX:** после того как менеджер написал боту, взять номер чата
   в `PROMIX_MAX_CHAT`, нажать «Отправить тестовое сообщение».

## 10. Проверка после переноса

- [ ] `https://домен/` — главная, все ссылки на свои (внешних ассетов нет).
- [ ] `/catalog/`, `/catalog/shpateli-i-lezviya/`, `/brand/storch/`, страница товара.
- [ ] Товар в корзину → `/cart/` → `/checkout/` → заказ: страница «Заказ принят»,
      письмо менеджеру на почту для заявок, письмо покупателю (если указал почту),
      сообщение в MAX, заказ в «WooCommerce → Заказы» со статусом «На удержании».
- [ ] Заявка через «Спросить у технолога»: письмо, MAX, запись в «Заявки».
- [ ] `/privacy-policy/` — без квадратных скобок в тексте.
- [ ] `/nope/` — своя 404.
- [ ] `/wp-content/themes/promix/README.md` и `/wp-content/themes/promix/_tools/`
      отвечают 403/404. На Apache это делает `.htaccess` темы, под nginx —
      правило из README («Перенос на сервер»).
- [ ] `/wp-sitemap.xml` открывается, `/robots.txt` не запрещает сайт.
- [ ] Галочка «не индексировать» снята (шаг 1.4).
- [ ] `http://` → `https://` редирект.

## Что вылезло на репетиции

- `flush_rewrite_rules()` в `wc-setup.php` записывал старые адреса: разделы и
  бренды отвечали 404. Исправлено — скрипт удаляет правила, WordPress собирает
  их при следующем запросе (потому шаг 5.4).
- Черновик «Политика конфиденциальности» от WordPress занимает ярлык
  `privacy-policy` — новая страница получает `-2`. Использовать черновик.
- Импорт с галочкой «Обновлять существующие» не создаёт новые товары —
  порядок в шаге 6 важен.
- Колонка цены в выгрузке из 1С называлась то «Цена», то «Цена, ₽» —
  `wc-import-csv.py` теперь ищет её по началу названия.
