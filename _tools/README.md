# Служебные скрипты

Порядок применения на новом сервере — в `DEPLOY.md` в корне репозитория.

Не часть темы. Нужны при развёртывании магазина на новом сервере (Local
сейчас, TimeWeb потом). В архив `git archive` не попадают (`export-ignore`
в `.gitattributes`), но при `git pull` прямо на сервере окажутся в
`wp-content/themes/promix/_tools/` — на Apache их закрывает `.htaccess`
в корне темы, под nginx нужен `location` из README (раздел «Перенос
на сервер»).

HPOS (хранение заказов в отдельных таблицах) включать только на чистой
базе до первого заказа: миграция уже существующих заказов — отдельная
процедура в «WooCommerce → Настройки → Дополнительно → Функции».

- `wc-setup.php` — настройка WooCommerce после активации: рубли, Россия,
  выключенные отзывы/купоны/налоги, страница каталога как «магазин», адреса
  `/catalog/…` и `/product/…`. Положить в корень сайта, заменить `СЕКРЕТ`,
  открыть `/wc-setup.php?k=СЕКРЕТ`, удалить файл.
- `wc-import-csv.py` — собирает `woo-import.csv` из прайса
  `docs/data/katalog-dlya-sayta.csv` (папка вне git), результат кладёт рядом;
  другой прайс — первым аргументом. Результат загружается через «Товары → Импорт»
  в админке; колонка Brands — штатные бренды WooCommerce («Товары →
  Бренды»), импортёр создаёт их сам.
- `wc-categories.py` — раскладывает прайс по разделам из документа заказчика
  «Для сайта.docx» (4 раздела, 27 подразделов). Правила раскладки — списки
  `RULES` (по ключевым словам в названии) и `OVERRIDES` (подраздел прямо по ID
  прайса) в самом скрипте; `--check` печатает раскладку, ничего не записывая.
  Пишет `wc-categories.csv` («Артикул;Раздел;Подраздел») и подменяет колонку
  «Категория» в прайсе на «Раздел > Подраздел», поэтому запускать его нужно
  **до** `wc-import-csv.py` и `wc-descriptions.py`.
- `wc-recategorize.php` — переводит на эти разделы уже наполненный магазин:
  заводит разделы в нужном порядке, переносит товары по артикулу, обновляет
  описания и удаляет опустевшие старые разделы. Рядом с ним нужны
  `wc-categories.csv` и `woo-descriptions.csv`. Положить в корень сайта,
  заменить `СЕКРЕТ`, открыть `/wc-recategorize.php?k=СЕКРЕТ` (с `&dry=1` —
  прогон без записи), после — удалить все три файла.
- `wc-descriptions.py` — собирает `woo-descriptions.csv` (артикул, краткое
  и полное описание) из того же прайса, туда же. Тип товара определяется по
  ключевым словам в названии (словарь `TYPES` в скрипте — туда же
  дописывать новые типы), бренд и раздел берутся как есть; выдуманных
  характеристик нет, о расходе и составе текст отсылает к паспорту
  производителя. Грузится через «Товары → Импорт» с галочкой «Обновлять
  существующие товары» — совпадение по артикулу. Краткое описание идёт
  в мета-описание страницы товара.
- `build-deploy.sh` — комплект для переноса в `docs/deploy/`: архив темы из
  текущего коммита, CSV заново из прайса, `wc-setup.php`, `wc-recategorize.php`,
  политика, DEPLOY.md и `СОСТАВ.txt` с коммитом и контрольными суммами.
  С незакоммиченными правками темы не собирает. Запуск:
  `bash _tools/build-deploy.sh`.

## Подключение MAX

1. В приложении MAX открыть **@MasterBot**, создать бота (`/newbot`), скопировать токен.
2. В `wp-config.php` добавить `define( 'PROMIX_MAX_TOKEN', '<токен>' );`.
3. Менеджер пишет боту любое слово (или добавляет бота в групповой чат
   и пишет там). В админке «Инструменты → MAX» появится номер чата.
4. В `wp-config.php` добавить `define( 'PROMIX_MAX_CHAT', <номер> );`.
5. Там же нажать «Отправить тестовое сообщение» — оно должно прийти в чат.

Дальше каждая заявка и каждый заказ уходят в этот чат сами. Если не
ушло — у заявки в списке пометка «в MAX не ушло», у заказа заметка
с текстом ошибки; письмо при этом всё равно отправляется.
