# Запуск PROMIX на чистом ПК

Инструкция для Windows 10/11 x64: Local + Git + клонирование ветки `main`.
Актуализирована 16.11.2026. На macOS порядок тот же, но пути к файлам и команды
PowerShell нужно заменить на соответствующие вашей системе.

В репозитории находится **тема WordPress**, а не вся установка сайта.
После клонирования можно редактировать PHP, CSS и JavaScript. Для просмотра
результата нужен локальный WordPress с WooCommerce.

Выберите результат:

| Что нужно | Что подготовить | Какие шаги выполнить |
| --- | --- | --- |
| Запустить тему и начать менять дизайн/код | Только репозиторий и программы ниже | 1–5, затем 7–9 |
| Получить копию наполненного магазина | Репозиторий, свежая база сайта, медиатека и нужные плагины | 1–4, затем 6–9 |

Без базы и медиатеки каталог рабочего сайта не восстановится. Файл
`docs/data/wc-variants.csv` защищает импорт, но не является выгрузкой магазина.

## 1. Установить программы

1. [Git for Windows](https://git-scm.com/downloads/win) — для клонирования
   и сохранения изменений. При установке разрешите использование Git
   из командной строки; остальные параметры можно оставить стандартными.
2. [Local](https://localwp.com/) — создаст WordPress и предоставит PHP,
   MySQL и веб-сервер. Отдельно ставить XAMPP, Open Server, PHP или MySQL не нужно.
3. Редактор кода, например [Visual Studio Code](https://code.visualstudio.com/).

После установки Git заново откройте PowerShell и проверьте:

```powershell
git --version
```

Должна появиться версия Git. Для чтения публичного репозитория вход
в GitHub не требуется. Для отправки своих изменений потребуется авторизация
под аккаунтом с правом записи.

Node.js, npm и Composer для обычного запуска темы не нужны: готовые ассеты
и библиотека Carbon Fields уже находятся в репозитории.

## 2. Создать сайт в Local

1. Запустите Local и выберите создание нового сайта (**Create a new site**).
2. Название: `promix`. В дополнительных параметрах задайте домен `promix.local`.
   Если он уже занят, используйте другой и замените его во всех примерах ниже.
3. Выберите окружение **Custom** с PHP **8.2**, если эта версия доступна,
   либо 8.3. Для веб-сервера и MySQL подойдут предлагаемые Local настройки.
   PHP 8.2 — исходный ориентир проекта; минимальная версия в теме — 8.1.
4. Задайте логин и пароль локального администратора и сохраните их.
5. Дождитесь установки, нажмите **Start site**, если сайт остановлен.
6. Через **Open site** убедитесь, что открывается стандартный WordPress.

Дальнейшие примеры используют `http://promix.local`. Если выбрали HTTPS,
доверяйте локальному сертификату средствами Local и используйте `https://`
последовательно во всех командах.

**В инструкции используются два разных терминала:** PowerShell для Git
и **Open Site Shell** выбранного сайта в Local для команд `wp`.
В Site Shell уже подготовлено окружение PHP/MySQL/WP-CLI; обычный PowerShell
может не находить команду `wp`.

## 3. Клонировать репозиторий в папку темы

В Local откройте папку сайта (**Go to site folder / Site folder**).
Внутри найдите `app/public/wp-content/themes`.

Если сайт создан в стандартном месте, выполните в **PowerShell**:

```powershell
$themeParent = Join-Path $env:USERPROFILE "Local Sites\promix\app\public\wp-content\themes"
Set-Location -LiteralPath $themeParent
git clone --branch main https://github.com/Lex973/Promix.git promix
Set-Location -LiteralPath (Join-Path $themeParent "promix")
git status --short --branch
git log -1 --oneline
```

Если Local выбрал другое расположение, замените значение `$themeParent`
на фактический абсолютный путь к `wp-content/themes`.
Команды выполняйте по очереди: если переход в папку не удался, сначала
исправьте путь. Папка назначения `promix` перед клонированием должна отсутствовать.

Проверьте из папки клонированной темы:

```powershell
Test-Path .\style.css
Test-Path .\functions.php
Test-Path .\vendor\autoload.php
Test-Path .\docs\data\wc-variants.csv
```

Все четыре результата должны быть `True`. Итоговая структура:

```text
Local Sites/promix/app/public/
  wp-config.php                 ← создан Local, находится вне Git
  wp-admin/
  wp-includes/
  wp-content/
    plugins/
    uploads/
    themes/
      promix/                   ← здесь корень клонированного репозитория
        .git/
        .codex/memory.md
        style.css
        functions.php
        assets/
        inc/
        vendor/
```

Не клонируйте репозиторий поверх всего `app/public` и не создавайте
дополнительную вложенность `themes/promix/Promix`.

## 4. Установить WooCommerce

Если восстанавливаете полный магазин, сначала прочитайте шаг 6.1:
для него нужны версии WordPress и плагинов, соответствующие исходному сайту.

Для новой установки нажмите **WP Admin** в Local и войдите с учётной записью
из шага 2. В админке:

1. **Плагины → Добавить новый** → найдите **WooCommerce** от Automattic.
2. Установите и активируйте плагин.
3. Дополнительные платёжные, рекламные и другие плагины мастера настройки
   для запуска PROMIX не требуются.
4. **Внешний вид → Темы** → активируйте **PROMIX**.

Carbon Fields отдельным плагином устанавливать не нужно — тема загружает его
из `vendor/`.

## 5. Настроить новую пустую установку

Этот шаг нужен, если **нет свежей копии базы**. Для восстановления наполненного
сайта переходите к шагу 6: его страницы и настройки придут из базы.

### Страницы и главная

1. **Страницы → Добавить новую**: «Главная». В настройках страницы выберите
   шаблон **Главная PROMIX** и опубликуйте её.
2. Создайте страницу «Каталог» с ярлыком **`catalog`** и пустым содержимым.
3. Откройте существующий черновик «Политика конфиденциальности», перенесите
   текст из [_content/privacy-policy.md](_content/privacy-policy.md) и опубликуйте.
4. Создайте «Согласие на обработку персональных данных» с ярлыком `soglasie`,
   перенесите текст из [_content/consent.md](_content/consent.md) и опубликуйте.
5. **Настройки → Чтение** → статическая главная → «Главная».
   Здесь же включите просьбу к поисковым системам не индексировать локальный сайт.
6. **Настройки → Конфиденциальность** → назначьте страницу политики.
7. Снова откройте редактирование «Главной»: поля секций находятся в редакторе
   этой страницы. Общие контакты и SEO-поля доступны через меню **Контакты PROMIX**.

### Страницы и адреса магазина

1. Если WooCommerce ещё не создал корзину и оформление, создайте две пустые
   страницы: «Корзина» (`cart`) и «Оформление заказа» (`checkout`).
2. **WooCommerce → Настройки → Товары** → страница магазина «Каталог».
3. **WooCommerce → Настройки → Дополнительно** → назначьте страницы корзины
   и оформления заказа. Их разметку выводит тема PROMIX.
4. В основных настройках WooCommerce установите рубли и Россию.
5. **Настройки → Постоянные ссылки** → выберите «Название записи».
   В параметрах WooCommerce на этой же странице задайте базу категорий товаров
   `catalog` и произвольную базу товаров `/product/`. Сохраните настройки.
6. Если WooCommerce показывает гостям заглушку «Скоро открытие», отключите её
   в настройках видимости магазина для локальной проверки.
7. Добавьте через **Товары → Добавить** один тестовый товар с ценой,
   изображением и категорией; опубликуйте его.

Теперь доступны главная, `/catalog/` и карточка тестового товара.
Полного ассортимента, фотографий и заполненных на сервере полей пока нет —
это ожидаемо. Пустая установка подходит для разработки темы с тестовыми данными.
Для проверки поведения вариантов можно создать тестовый вариативный товар.

Не запускайте старые скрипты импорта или объединения ради восстановления
актуального магазина: для него используйте свежую базу по следующему шагу.

## 6. Восстановить наполненный магазин

Все действия этого раздела выполняются **только с новым локальным сайтом**.
Импорт базы заменяет его содержимое и учётные записи.

### 6.1. Подготовить комплект переноса

С рабочего сайта или из свежей резервной копии отдельно получите:

- полный SQL-дамп базы, включая таблицы WooCommerce и HPOS;
- всю папку `wp-content/uploads` с сохранением вложенных каталогов;
- список версий WordPress и активных плагинов; файлы нужных плагинов,
  если их нельзя получить из официального каталога;
- сведения о дополнительных `mu-plugins`, если они используются.

Панель хостинга позволяет выгрузить базу и файлы. При доступе к WP-CLI
на исходном сайте команда `wp db export` также создаёт SQL-дамп;
это делают в окружении исходного сайта, отдельно от локальных команд ниже.
Обычный XML-экспорт «Инструменты → Экспорт» не заменяет полный SQL-дамп.

Сверьте дату комплекта: старые `before.sql` из отчётов — снимки **до** изменений.
Локальный `workspace-before-sync.zip` также не является свежей копией серверного
магазина. База и медиатека должны относиться к одному состоянию сайта.

Положите распакованный SQL, например, в `C:\Transfer\Promix\site.sql`.
Храните комплект вне публичного репозитория и вне доступной через браузер
папки `app/public`.

В Local используйте ту же версию WordPress и WooCommerce, что на исходном сайте,
и восстановите нужные плагины. Если Local создал другую версию WordPress,
согласуйте её с комплектом до первого открытия восстановленной базы.
Тему `wp-content/themes/promix` оставьте клонированной из GitHub;
не заменяйте её старой копией из архива. `mu-plugins` с привязкой к хостингу
переносятся после проверки их назначения.

### 6.2. Подготовить файлы и локальную конфигурацию

1. Скопируйте содержимое серверной `uploads` в
   `Local Sites/promix/app/public/wp-content/uploads`.
   Проверьте, что не получилось `uploads/uploads`.
2. Оставьте `wp-config.php`, созданный Local: его `DB_HOST`, `DB_NAME`,
   `DB_USER`, `DB_PASSWORD` указывают на локальную базу.
   Серверный конфиг целиком поверх него не копируйте.
3. Откройте SQL в редакторе и найдите название таблицы, заканчивающееся
   на `_options`, например `wp_options`. Префикс всех таблиц этой установки
   должен совпадать с `$table_prefix` в локальном `wp-config.php`.
   Если в дампе `abc_options`, локальное значение должно быть `'abc_'`.
4. Для разработки оставьте `PROMIX_SMTP_HOST`, `PROMIX_SMTP_PASS`,
   `PROMIX_MAX_TOKEN` и `PROMIX_MAX_CHAT` незаданными. Теме они не нужны
   для отображения сайта. Плагины внешних интеграций из копии сайта
   отключите до проверки локальной копии.

### 6.3. Импортировать базу и заменить адрес

В Local выберите **именно локальный сайт `promix`**, запустите его и нажмите
**Open Site Shell**. Команды ниже выполняются в этом окне из `app/public`,
где находятся `wp-config.php` и `wp-admin`.

Проверьте, что WP-CLI работает, и импортируйте SQL:

```text
wp --info
wp db import "C:/Transfer/Promix/site.sql"
```

Затем назначьте локальные адреса, пока не открывая сайт в браузере:

```text
wp option update home "http://promix.local" --skip-plugins --skip-themes
wp option update siteurl "http://promix.local" --skip-plugins --skip-themes
```

Замените адрес рабочего сайта в базе. Сначала выполните пробный запуск:

```text
wp search-replace "https://promix-kazan.ru" "http://promix.local" --all-tables-with-prefix --skip-columns=guid --precise --dry-run --skip-plugins --skip-themes
```

Если отчёт завершился без ошибок, выполните замену:

```text
wp search-replace "https://promix-kazan.ru" "http://promix.local" --all-tables-with-prefix --skip-columns=guid --precise --skip-plugins --skip-themes
```

Если дамп получен с другого домена, используйте **его исходный адрес**.
Для дополнительных вариантов адреса, реально присутствующих в базе
(например, `http://` или `www`), повторите пробный и обычный запуск отдельно.
WP-CLI корректирует сериализованные значения; обычная текстовая замена
по SQL-файлу может повредить настройки.

Чтобы при первом открытии восстановленная копия не запустила фоновые задачи
рабочего магазина, отключите автоматический WP-Cron локально:

```text
wp config set DISABLE_WP_CRON true --raw
wp option update blog_public 0 --skip-plugins --skip-themes
```

Вернуть фоновые задачи для отдельной проверки можно позже, после отключения
рабочих интеграций. Флаг `--skip-plugins` в командах не отключает плагины
постоянно и не пропускает `mu-plugins`.

### 6.4. Войти и закончить настройку

После импорта действуют **пользователи из перенесённой базы**. Логин,
созданный Local в шаге 2, может больше не существовать.
Войдите с учётными данными исходного сайта либо через One-click Admin в Local.

Если доступа нет, в **локальном Site Shell** посмотрите список пользователей:

```text
wp user list --fields=ID,user_login,roles --skip-plugins --skip-themes
```

Для нужного администратора можно задать новый пароль только в этой локальной
базе. Вместо `ADMIN_LOGIN` подставьте его логин; пароль вводится по запросу:

```text
wp user update ADMIN_LOGIN --prompt=user_pass --skip-email --skip-plugins --skip-themes
```

В админке проверьте активность WooCommerce и темы PROMIX. Отключите плагины
платежей, SMTP и внешних интеграций, не предназначенные для локального запуска.
Затем сохраните **Настройки → Постоянные ссылки** и проверьте главную,
каталог, изображения, варианты, корзину и оформление.
Шаблон «Главная PROMIX», назначение главной и страниц WooCommerce обычно
уже восстановлены из базы; при необходимости сверьтесь с шагом 5.

Не повторяйте миграцию объединения товаров после импорта актуальной базы:
варианты уже находятся в ней. Сохраняйте `docs/data/wc-variants.csv` рядом
с используемым прайсом при последующих обычных импортах.

## 7. Проверить результат

- Открывается `http://promix.local`, адрес не меняется на рабочий домен.
- В `/wp-admin/` доступны поля главной и «Контакты PROMIX».
- На `/catalog/` отображаются тестовые или восстановленные товары.
- Карточка товара показывает цену и фото, выбор варианта работает.
- Товар добавляется в корзину, количество меняется, оформление открывается.
- При восстановлении полной копии количество товаров и вариантов
  совпадает с выбранным свежим снимком. Числа из старых отчётов не являются
  постоянным эталоном текущего каталога.
- После изменения CSS и обновления страницы видны новые стили.

Проверку писем без рабочего SMTP можно выполнить через
**Local → Tools → Mailpit → Open Mailpit**: там видны письма, отправленные
стандартным механизмом PHP. Настроенный отдельным плагином внешний SMTP
может обходить этот перехват.

## 8. Редактировать и сохранять работу

Откройте в редакторе именно `app/public/wp-content/themes/promix`.

| Что менять | Где |
| --- | --- |
| Оформление страниц | `assets/css/` |
| Поведение элементов | `assets/js/` |
| Шаблоны и разметку | `front-page.php`, `single-product.php`, `template-parts/` |
| Логику темы | `inc/`, `functions.php` |
| Тексты главной и контакты | В админке WordPress |
| Товары, цены, фото и варианты | В админке WooCommerce |
| Контекст прошлых работ | `.codex/memory.md`, `AGENTS.md` |

Изменения PHP/CSS/JS сохраняются в Git. Изменения в админке записываются
в локальную базу, новые фотографии — в локальную `uploads`: обычный `git push`
их не переносит.

Перед работой в PowerShell из папки темы:

```powershell
git switch main
git pull --ff-only origin main
git switch -c work/my-change
```

Если уже есть незакоммиченные изменения, сначала сохраните их; при сообщении
об ошибке не продолжайте команды вслепую. Для каждого нового изменения
используйте свободное имя ветки.

Один раз настройте имя и email для коммитов, подставив свои данные:

```powershell
git config user.name "YOUR_NAME"
git config user.email "YOUR_GITHUB_EMAIL"
```

После правок и проверки в браузере:

```powershell
git status
git diff
git add --all
git diff --cached --stat
git commit -m "Describe the change"
git push -u origin work/my-change
```

При первом push авторизуйтесь в GitHub через предложенный Git механизм.
На GitHub создайте Pull Request из своей ветки в `main` и выполните слияние.
Проверяйте состав коммита: репозиторий публичный, секреты и дампы туда не входят.

Для переноса изменений базы между ПК нужны отдельные экспорт базы и копия
`uploads`. Для публикации темы на рабочий сайт используйте
[DEPLOY.md](DEPLOY.md). Отправка кода в GitHub сама по себе не загружает тему
на хостинг. Локальную базу с тестовыми заказами поверх рабочей не импортируйте.

## 9. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `git` не найден | Переоткрыть PowerShell после установки Git; проверить добавление Git в PATH |
| `wp` не найден | Открыть **Open Site Shell** в Local, сайт должен быть запущен |
| `destination path 'promix' already exists` | Проверить папку: если репозиторий уже клонирован, открыть её и выполнить `git status`; повторное клонирование не нужно |
| Тема не появляется | Файлы `style.css` и `functions.php` должны лежать прямо в `wp-content/themes/promix` |
| PHP-файл открывается как текст | Открывать сайт кнопкой Local, а не файл через `file://` или VS Code Live Server |
| Каталог пустой | На чистой установке добавить тестовые товары; для полного каталога импортировать свежую базу |
| Нет фотографий | Скопировать `uploads`, проверить отсутствие вложенной `uploads/uploads` и выполнить замену адресов |
| Нет полей главной | Проверить `vendor/autoload.php`, шаблон «Главная PROMIX» и назначение статической главной |
| Каталог или товар отвечает 404 | Проверить активность WooCommerce, назначение магазина и сохранить постоянные ссылки |
| После импорта предлагает установить WordPress | Проверить `$table_prefix` и наличие импортированных таблиц в локальной базе; не запускать установку повторно |
| Пароль Local больше не подходит | После импорта пользователи взяты из дампа; см. шаг 6.4 |
| Перенаправляет на рабочий сайт | Проверить `home`, `siteurl`, замену адресов, константы `WP_HOME`/`WP_SITEURL` и перенесённые плагины редиректов |
| Стили не обновились | Сделать жёсткое обновление `Ctrl+F5`, проверить путь редактируемой темы и её активность |
